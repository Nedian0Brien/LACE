token 조각 복원이 아니라, 의미 chunk를 먼저 세우고 문장을 확장한다.

S4g는 pretrained decoder를 붙여도 새 span을 의미 있게 생성하지 못했다. 그래서 S5의 핵심은 모델을 더 키우는 것이 아니라, reverse process의 단위를 subword 조각에서 의미 있는 word/chunk 단위로 바꾸는 것이다.

핵심 직관: 뼈대 토큰 사이의 빈칸을 "쉼표 하나"로 맞히는 문제가 아니라, "이 자리에는 어떤 의미 단위가 들어가야 하는가"를 먼저 맞히는 문제로 바꾼다.
one sentence summary

먼저 의미 계획, 그 다음 표면 문장.

`고양이 / 창가 / 잠들었다`라는 skeleton에서 바로 subword를 맞히지 않는다. 먼저 `검은`, `조용히` 같은 의미 chunk를 고르고, 이후 조사·어미·쉼표를 붙여 자연문으로 만든다.

01 · why S4g failed

현재 구조는 의미 확장이 아니라 조각 맞히기로 변질됐다

같은 원문을 두 방식으로 보면 문제가 바로 보인다. 우리가 원하는 것은 오른쪽인데, S4g가 실제로 학습한 문제는 왼쪽에 가까웠다.

02 · proposed structure

S5: Semantic Plan Bridge

구조는 다섯 부분으로 나눈다. 중요한 점은 gap 하나가 독립 token 위치가 아니라, 좌우 anchor 사이에 있는 의미 query가 된다는 것이다.

1
Skeleton Encoder
현재 남아 있는 의미 골격, 위치, transition ratio를 encoding한다.
2
Gap Query Builder
연속된 빈칸을 하나의 span query로 묶고 좌우 anchor를 찾는다.
3
Anchor Attention
query가 left/right anchor와 전체 skeleton을 직접 attention한다.
4
Semantic Planner
이 gap에 들어갈 content chunk를 먼저 예측한다.
5
Surface Realizer
content chunk에 조사, 어미, punctuation을 붙여 문장 span으로 실현한다.
03 · visual model

anchor는 prompt 설명이 아니라 query가 직접 참고하는 표현이다

S4g에서는 anchor 정보가 문자열 prompt 안에 들어갔다. S5에서는 gap query가 anchor representation을 직접 보는 구조로 바뀐다.

left anchor 고양이
position 창가 앞
gap query 어떤 의미가 들어갈까?
transition 0.25 → 0.50
right anchor 창가
query attends to anchors and global skeleton
global 고양이 · 창가 · 잠들었다
semantic plan 검은
surface span 검은 고양이가
insert current state 갱신
next step 더 세부 span 확장
principle 1
단위 변경

subword span이 아니라 word/chunk span을 기본 예측 단위로 둔다.

principle 2
순서 변경

content chunk를 먼저 만들고 function/punctuation은 뒤에서 실현한다.

principle 3
anchor 직접 사용

anchor를 prompt text가 아니라 span query의 attention 대상으로 만든다.

principle 4
metric 분리

final rollout과 generated-span-only content/entity를 분리해서 본다.

06 · experiment gates

S5가 확인해야 할 것

이 구조가 좋은 연구 실험이 되려면 final score만 보면 안 된다. S4g에서 이미 final score와 span generation이 분리된다는 걸 봤기 때문이다.
