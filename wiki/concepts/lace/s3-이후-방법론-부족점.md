# S3 이후 방법론 부족점

S3 이후의 핵심 상태는 [[concepts/lace/s3-anchor-baseline-comparison|S3-anchor baseline comparison]]이 실패했다는 사실 자체보다, 실패의 원인이 아직 충분히 분해되지 않았다는 점이다.

현재 부족한 것은 "더 큰 모델" 하나가 아니라, [[concepts/lace/의미-골격|의미 골격]] terminal state가 실제로 더 나은 [[concepts/lace/위치-보조-구조|위치 보조 구조]] 기반 reverse trajectory를 만드는지 식별할 수 있는 방법론이다.

## 부족한 점

첫째, `better reverse trajectory`의 운영 정의가 아직 약하다. 현재 S3 score는 Token F1, ROUGE-L, loss bonus의 합성값이지만, 이 값은 실제 의미 복원, 생성 안정성, terminal 정보 사용을 분리하지 못한다.

둘째, random terminal baseline이 충분히 약한지 확인되지 않았다. S3에서는 `random_forward_no_anchor`가 가장 높은 score를 얻었으므로, random terminal이 위치 편향, 빈출 token prior, 문장 길이 prior를 통해 예상보다 강해졌을 가능성이 있다.

셋째, anchor baseline이 강하지 않았다. S3 anchor 조건은 gold anchor가 아니라 predicted anchor를 사용했고, anchor predictor의 Token F1은 낮았다. 따라서 S3는 "강한 anchor prediction baseline을 이겼는가"를 확인한 실험이 아니다.

넷째, scorer 선택 문제가 남아 있다. attention, idf, position-prior 계열이 서로 다른 강점을 보였지만, 어떤 scorer가 semantic terminal state로 가장 적합한지 아직 결정되지 않았다.

다섯째, 현재 reverse probe가 terminal 정보량 차이에 충분히 민감한지 불분명하다. 생성 샘플에는 반복과 표면 token prior가 많았고, lexical metric은 이런 문장 prior의 영향을 받을 수 있다.

여섯째, 위치 편향과 content 사용이 완전히 분리되지 않았다. S2에서는 same-position random과 wrong-document control이 유효했지만, S3에서는 `same_position_random_terminal`, `position_only`, `gold_anchor_oracle`이 아직 함께 비교되지 않았다.

## 다음 방법론 설계의 기준

다음 방법론은 곧바로 S4 generation으로 가기보다, 먼저 S3a 진단으로 측정 장치를 고쳐야 한다.

좋은 S3a는 다음 질문에 답해야 한다.

- gold anchor를 주면 복원 probe가 실제로 좋아지는가?
- predicted anchor만 약한가, 아니면 anchor 방식 자체가 약한가?
- random terminal의 강함은 위치/길이/빈출어 prior 때문인가?
- attention terminal, idf terminal, same-position random terminal 사이의 정보량 차이가 metric에 드러나는가?
- 현재 lexical metric 외에 terminal information use를 더 직접적으로 보는 metric이 필요한가?

방어 가능한 다음 결론은 다음과 같다.

> S3 이후의 부족점은 semantic skeleton 가설 자체의 부재가 아니라, terminal state의 정보량, 위치 편향, anchor predictor 병목, lexical metric 민감도를 분리하는 식별 방법론의 부족이다.
