# LACE 연구노트 초안

**작성 시작일**: 2026-05-04  
**연구명**: LACE, Latent Adaptive Compression and Expansion for Language Diffusion  
**논문 가제**: Compression, Not Corruption  
**현재 상태**: Phase 0부터 Phase 3A까지의 초기 실험 정리

이 문서는 지금까지 진행한 LACE 연구의 문제의식, 핵심 방법론, 세부 연구 질문, 검증 시도, 결과 및 시사점을 한 곳에 정리하기 위한 연구노트 초안이다. 이후에는 실험이 추가될 때마다 이 문서에 판단, 반론, 설계 변경, 다음 질문을 이어 적는다.

## 1. 해결하려고 하는 문제

Diffusion Language Model, 이하 DLM은 autoregressive language model과 달리 여러 token을 병렬적으로 갱신하고, 양방향 문맥을 활용하며, 생성 중간 상태를 반복적으로 수정할 수 있다는 장점이 있다. 그러나 텍스트에 diffusion을 적용할 때 가장 애매한 부분은 forward process의 정의다.

이미지 diffusion에서는 Gaussian noise를 더하는 과정이 비교적 자연스럽다. 그러나 언어는 discrete token과 구조화된 의미를 가진다. 따라서 기존 DLM에서 많이 사용하는 mask, random replacement, Gaussian noise류 forward process는 언어의 의미 구조를 점진적으로 추상화한다기보다, 표현을 임의로 손상시키는 과정에 가깝다.

이 연구의 출발점은 다음 질문이다.

> 언어 생성에서 diffusion time은 noise severity가 아니라 information rate로 정의되어야 하지 않을까?

즉, LACE는 원문 표현을 무작위로 망가뜨리는 대신, token-level latent representation을 점진적으로 압축하고, reverse process에서 다시 더 상세한 표현으로 확장하는 경로를 DLM의 forward/reverse trajectory로 볼 수 있는지 검증한다.

이때 주의해야 할 점은 LACE가 단순히 "hidden state를 압축하고 복원하는 autoencoder"를 만들려는 연구가 아니라는 것이다. hidden-state reconstruction은 중간 검증 지표일 뿐이다. 최종적으로 중요한 질문은 다음이다.

> Compression-based forward process가 corruption/noise/masking 기반 forward process보다 language generation에 더 적합한 reverse learning path를 제공하는가?

## 2. 핵심 방법론

현재 구현에서 LACE는 frozen `t5-small` encoder를 사용해 입력 text를 token-level hidden state로 변환한다.

```text
text x
→ frozen T5 encoder
→ h0 ∈ R^{N × d}
```

여기서 `h0`는 원문 token sequence의 latent representation이다. 이후 forward process는 `h0`를 여러 단계의 낮은 token budget latent로 압축한다.

```text
h0: 128 tokens
→ z1: 64 tokens
→ z2: 32 tokens
→ z3: 16 tokens
```

초기 연구에서 비교한 forward process 후보는 다음과 같다.

| 후보 | 성격 | 역할 |
|---|---|---|
| `average_pool` | deterministic compression | 가장 단순하고 해석 가능한 compression baseline |
| `strided_select` | deterministic token selection | token budget은 줄이지만 평균화는 하지 않는 비교군 |
| `random_select` | stochastic drop/corruption | 같은 token budget을 가진 corruption baseline |
| `gaussian_noise` | continuous corruption | 기존 latent diffusion류 reference |
| learned attention compression | adaptive compression | 장기적으로 필요한 후보지만 초기에는 confound가 큼 |
| positional conditioning | reverse expansion scaffold | 압축 중 약해지는 위치/순서 정보를 보완하는 후보 |

Reverse process는 압축된 latent에서 `h0` 또는 더 상세한 latent를 복원하는 expander를 학습한다.

```text
z_t
→ Expander
→ h0_hat
```

평가 지표는 여러 층으로 분리해서 본다.

| 지표군 | 보는 것 | 왜 필요한가 |
|---|---|---|
| hidden-state MSE | 좌표값 복원 품질 | 가장 기본적인 reconstruction 가능성 |
| cosine similarity | representation 방향성 | 의미/방향 구조가 보존되는지 확인 |
| variance ratio | collapse 또는 scale 폭주 여부 | MSE만 낮은 비정상 복원 방지 |
| perturbation / ablation / swap | latent를 실제로 쓰는지 | expander가 평균 패턴만 찍는지 확인 |
| frozen decoder NLL | T5 decoder가 `h0_hat`를 읽을 수 있는지 | token-level reconstruction proxy |
| lightweight token-head NLL | decoder-specific confound를 줄인 token proxy | token 정보 보존성 확인 |
| open-ended generation | 자유 생성이 가능한지 | 최종 generation path와의 연결 |

이 분리는 매우 중요하다. MSE가 낮다고 generation이 되는 것은 아니고, cosine이 높다고 token reconstruction이 좋은 것도 아니다. 현재까지의 실험은 이 차이를 계속 확인해 왔다.

## 3. 세부 연구 질문

### RQ1. Compression은 DLM forward process가 될 수 있는가?

핵심 질문이다. 단순히 압축 latent를 복원할 수 있는지가 아니라, 같은 reverse model과 같은 데이터 조건에서 compression forward가 random corruption이나 Gaussian noise보다 더 좋은 reverse learning path를 제공하는지 묻는다.

좋은 결과는 compression condition이 MSE, cosine, token proxy, latent-use, generation 중 복수의 지표에서 corruption baseline보다 일관된 장점을 보이는 것이다. 나쁜 결과는 compression이 hidden reconstruction에만 일부 유리하고 token/generation으로 이어지지 않는 것이다.

### RQ2. Reverse expander는 latent를 실제로 사용하는가?

Expander가 입력 latent를 무시하고 평균적인 hidden trajectory만 찍어내면 LACE의 핵심 주장은 무너진다. 따라서 perturbation sensitivity, latent ablation, latent swap을 통해 latent-conditioned 복원이 실제로 일어나는지 확인해야 한다.

좋은 결과는 latent를 흔들거나 제거하거나 바꿨을 때 reconstruction이 악화되는 것이다. 나쁜 결과는 MSE가 낮더라도 ablation/swap에 거의 반응하지 않는 것이다.

### RQ3. Hidden reconstruction과 language usability는 같은가?

현재까지의 중요한 발견은 둘이 같지 않다는 점이다. 어떤 condition은 MSE가 낮지만 decoder NLL이나 generation이 좋지 않고, 어떤 condition은 MSE에서 압도하지 못해도 frozen decoder proxy에서 상대적으로 유리하다.

따라서 LACE의 평가는 hidden-state reconstruction quality, representation direction, token-level reconstruction proxy, open-ended generation behavior를 분리해야 한다.

### RQ4. Average Pooling은 단순하지만 충분한 baseline인가?

Average Pooling은 새롭거나 복잡한 방법은 아니다. 그러나 초기 연구에서는 오히려 장점이 있다. learned compressor의 불안정성을 제거하고, compression forward process 자체가 corruption보다 나은지 해석하기 쉽기 때문이다.

좋은 결과는 Average Pooling이 random selection보다 구조적이고, Gaussian noise보다 decoder/token 경로에서 유리한 신호를 보이는 것이다. 나쁜 결과는 Average Pooling의 이점이 position prior나 expander capacity로 설명되는 것이다.

### RQ5. Learned Attention Compression은 언제 필요한가?

Learned Attention Compression은 장기적으로 중요한 후보지만, 초기부터 핵심 가설의 대표로 삼기에는 위험하다. 실패했을 때 compression 가설이 나쁜 것인지, attention compressor 설계가 나쁜 것인지 분리하기 어렵다.

현재까지의 결과는 learned attention이 pooling보다 불안정하다는 쪽이다. 따라서 attention compression은 anchor loss, scale regularization, direct-to-h0 loss 같은 안정화 장치가 필요하다.

### RQ6. Positional information은 compression reverse expansion에 필수인가?

Average Pooling은 block 내부 token의 순서와 위치 정보를 약하게 만든다. Phase 2C는 explicit positional encoding이 reverse expansion을 안정화하는지 검증했다.

좋은 결과는 positional conditioning이 Average Pooling의 MSE/cosine/token proxy를 개선하면서도 position-only control보다 명확히 나은 것이다. 현재 결과는 proxy 개선은 강했지만, position-only와 Gaussian positional도 강해 confound가 남았다.

### RQ7. Generation-capable reverse objective가 필요한가?

지금까지의 open-ended generation은 대부분 붕괴했다. 이는 reconstruction-only objective가 decoder-readable hidden state를 만들기에는 부족하다는 신호일 수 있다.

다음 단계에서는 token-head loss 또는 generation-aware objective를 reverse expansion 학습에 직접 넣어야 한다.

```text
L = L_hidden_rec
  + lambda_cos * L_cos
  + lambda_token * L_token_head
```

## 4. 방법론을 입증하기 위한 시도와 결과

### Phase 0. Latent Cache 및 Pooling Sanity Check

**목적**

가장 작은 실행 단위를 검증했다. Kaggle GPU에서 `t5-small` encoder를 돌리고, 텍스트를 `h0` latent로 만들고, average pooling으로 `z1/z2/z3`를 생성한 뒤, latent cache가 안정적으로 저장/재로딩되는지 확인했다.

**결과**

```text
z1 MSE:    0.008886, cosine: 0.787159
z2 MSE:    0.013866, cosine: 0.642822
z3 MSE:    0.017505, cosine: 0.522215
cache_allclose: true
```

**시사점**

압축이 강해질수록 MSE가 증가하고 cosine이 감소하는 자연스러운 곡선이 확인됐다. 이 결과는 LACE 가설을 입증하지는 않지만, 이후 실험을 위한 latent pipeline이 살아 있음을 보여줬다.

### Phase 1. Reverse Expander 학습 가능성 확인

**목적**

압축된 latent에서 `h0`를 복원하는 expander가 실제로 학습되는지 확인했다. fallback corpus와 WikiText-2 subset에서 pooling과 learned attention compression을 비교했다.

**결과**

WikiText-2 subset에서 pooling은 stage 곡선을 유지했다.

```text
pooling z1 MSE: 0.010499, cosine: 0.805115
pooling z2 MSE: 0.016689, cosine: 0.659220
pooling z3 MSE: 0.020779, cosine: 0.544056
```

그러나 perturbation sensitivity가 낮아 overall gate는 실패했다.

```text
pooling perturbation sensitivity: 0.002050
```

Learned attention compression은 pooling보다 훨씬 나빴다.

```text
attention z3 MSE: 0.123256
attention z3 cosine: 0.236275
attention variance ratio: 약 3.8
```

**시사점**

Pooling은 단순하지만 안정적인 baseline으로 사용할 수 있다. 반면 learned attention compression은 현재 구조로는 불안정하다. attention latent에는 pooled-latent anchor, direct-to-h0 reconstruction, scale regularization이 필요해 보인다.

이 단계에서 중요한 판단은 다음이다.

> Learned compression을 바로 핵심 방법론으로 밀기보다, 먼저 fixed compression forward process와 corruption baseline을 비교하는 것이 더 해석 가능하다.

### Phase 2. Forward Process Isolation

**목적**

LACE의 핵심 질문으로 이동했다. 같은 데이터, 같은 frozen encoder, 같은 reverse expander에서 compression forward process가 corruption/noise forward process보다 나은 reverse learning 조건을 제공하는지 비교했다.

비교 조건은 다음이었다.

```text
average_pool
strided_select
random_select
gaussian_noise
```

**결과**

자동 gate는 모두 pass였지만, 실제 해석은 partial success였다.

평균 지표:

```text
average_pool MSE:             0.936960
random_select MSE:            0.922394
gaussian_noise MSE:           0.862077

average_pool cosine:          0.304123
random_select cosine:         0.203049
gaussian_noise cosine:        약 0.235703

average_pool delta token NLL: 6.542922
random_select delta token NLL:7.162894
gaussian_noise delta NLL:     7.454267
```

**시사점**

MSE 기준으로는 Average Pooling이 강하지 않았다. 그러나 cosine과 frozen decoder token reconstruction bridge에서는 Average Pooling이 더 좋은 신호를 보였다. 즉, compression forward process의 장점이 hidden 좌표 복원보다 representation direction 또는 decoder-readability 쪽에 있을 가능성이 생겼다.

동시에 open-ended generation은 여전히 좋지 않았다. 따라서 "token proxy에서 좋다"와 "자유 생성이 된다"를 분리해야 한다는 교훈을 얻었다.

### Phase 2B. Calibrated Forward Validation

**목적**

Phase 2 결과의 반론을 줄이기 위해 실험을 더 엄격하게 만들었다.

주요 변경은 다음이다.

```text
samples: 512 → 2048
epochs: 2 → 4
Gaussian sigma: matched calibration 적용
h0 decoder control 추가
lightweight token-head bridge 추가
gate를 MSE, cosine, decoder NLL, token-head NLL, latent-use, generation으로 분리
```

**결과**

Strict overall pass는 실패했지만, Phase 3 candidate 기준은 조건부로 통과했다.

핵심 평균 지표:

```text
average_pool MSE:             0.450913
random_select MSE:            0.443378
matched gaussian MSE:         0.439971

average_pool cosine:          0.309039
random_select cosine:         0.127890
matched gaussian cosine:      0.357422

average_pool decoder dNLL:    8.152192
random_select decoder dNLL:   8.302068
matched gaussian decoder dNLL:8.498025

average_pool token-head dNLL: 1.441394
matched gaussian token-head:  1.074497

h0 meaningful generation:     0.75
average_pool meaningful gen:  0.00
```

Gate 결과:

```text
P2B-G-RUN: pass
P2B-G-MSE: fail
P2B-G-COS: fail
P2B-G-DECODER-NLL: pass
P2B-G-TOKEN-HEAD-NLL: fail
P2B-G-USE: pass
P2B-G-GEN: fail
```

**시사점**

Average Pooling은 matched Gaussian과 비교했을 때 hidden MSE/cosine에서 강한 우위를 보이지 못했다. 하지만 frozen decoder delta NLL과 latent-use 신호는 유지됐다.

따라서 방어 가능한 해석은 다음이다.

> Average Pooling compression은 hidden-state 좌표 복원에서 최강은 아니지만, frozen decoder가 읽기 쉬운 정보를 일부 보존할 가능성이 있다. 다만 이 신호는 token-head나 open-ended generation으로는 아직 충분히 이어지지 않았다.

특히 h0 control은 의미가 컸다. 원본 `h0`에서는 generation이 되는데 reconstructed `h0_hat`에서는 무너졌기 때문에, generation 실패를 단순 decoder bridge 문제로만 설명하기 어려워졌다.

### Phase 2C. Adding Positional Encoding

**목적**

Average Pooling이 open-ended generation에서 무너진 원인 중 하나가 위치/순서 정보 부족인지 검토했다. Expander에 fixed sinusoidal positional feature를 추가하고, position-only control과 Gaussian positional control을 함께 넣었다.

비교 조건:

```text
average_pool
average_pool_positional
position_only
random_select
gaussian_noise
gaussian_noise_positional
```

**결과**

Positional conditioning은 proxy 지표를 크게 개선했다.

```text
average_pool MSE:              0.450913
average_pool_positional MSE:   0.020764

average_pool cosine:           0.309039
average_pool_positional cosine:0.553341

average_pool decoder dNLL:     8.152192
average_pool_positional dNLL:  5.050653

average_pool token-head dNLL:  1.441394
average_pool_positional dNLL:  0.486786
```

그러나 position-only와 Gaussian positional control도 매우 강했다.

```text
position_only MSE:             0.026878
position_only decoder dNLL:    5.295180
position_only token-head dNLL: 0.176166

gaussian_noise_positional MSE:             0.014739
gaussian_noise_positional cosine:          0.722765
gaussian_noise_positional decoder dNLL:    4.044799
gaussian_noise_positional token-head dNLL: 0.049600
gaussian_noise_positional meaningful gen:  0.333333
```

Gate 결과:

```text
P2C-G-RUN: pass
P2C-G-POS-MSE: pass
P2C-G-POS-COS: pass
P2C-G-POS-DECODER-NLL: pass
P2C-G-POS-TOKEN-HEAD-NLL: pass
P2C-G-POS-USE: pass
P2C-G-POS-CONTROL: fail
P2C-G-POS-MATTERS: pass
P2C-G-GEN: fail
overall_pass: false
phase3_candidate: false
```

**시사점**

Positional Encoding은 reverse expansion을 강하게 안정화한다. 그러나 이 효과는 Average Pooling compression의 고유 장점이라기보다, position-aware expander가 hidden trajectory를 훨씬 쉽게 복원하도록 돕는 일반 scaffold 효과에 가깝다.

특히 position-only가 token-head에서 매우 강했다는 점은 중요한 confound다. Content latent 없이도 위치 prior와 expander capacity만으로 token proxy가 상당히 좋아질 수 있다.

또한 Gaussian positional이 generation에서 유일하게 meaningful rate 0.333333을 보였기 때문에, length-preserving noisy hidden state와 positional scaffold의 조합이 compressed latent보다 generation path에 더 잘 맞을 가능성도 생겼다.

현재 방어 가능한 결론은 다음이다.

> Positional information은 LACE에서 반드시 다뤄야 할 요소다. 그러나 positional improvement만으로 Average Pooling compression의 우위를 주장할 수는 없다. 다음 실험은 position prior와 content latent contribution을 더 날카롭게 분리해야 한다.

### Phase 2D. Positional Confound Bridge

**목적**

Phase 2D는 Phase 3A로 가기 위한 중간 다리로 진행했다. Phase 3A가 더 중요한 실험이라는 판단은 유지하되, token/generation-aware objective를 넣기 전에 positional confound를 정리해야 했다.

Phase 2C의 문제는 explicit positional encoding이 너무 강했다는 점이다. Average Pooling positional이 좋아진 것은 사실이지만, position-only와 Gaussian positional도 강했다. 따라서 Phase 3A에서 token loss를 바로 넣으면, 개선이 content latent 때문인지 positional shortcut 때문인지 해석하기 어려웠다.

Phase 2D는 다음을 분리했다.

```text
absolute position
block-relative position
absolute + block-relative position
position-only controls
matched Gaussian positional control
wrong-position shift sweep
shuffled-label delta NLL
```

**결과**

핵심 평균 지표:

```text
average_pool MSE:             0.450913
average_pool_abs_pos MSE:     0.020764
average_pool_rel_pos MSE:     0.020711
average_pool_abs_rel_pos MSE: 0.020933

average_pool_rel_pos decoder dNLL:      4.775901
average_pool_abs_rel_pos decoder dNLL:  5.010779
position_only_rel_pos decoder dNLL:     5.711123
position_only_abs_rel_pos decoder dNLL: 5.438735

average_pool_abs_rel_pos shuffled decoder delta: 1.239660
position_only_abs_rel_pos shuffled decoder delta: 0.520510
gaussian_noise_abs_pos shuffled decoder delta:   2.588585
```

Gate 결과는 실행 직후 summary에서는 `phase3_bridge_ready=false`로 기록됐다. 그러나 이는 모델 결과 문제가 아니라 gate 집계 버그였다. `P2D-G-POS-MATTERS`가 wrong-position sweep을 보겠다고 해놓고 실제로는 shift=1의 평균 delta만 threshold와 비교하고 있었다. runner를 수정해 sweep max delta를 함께 보도록 바꾼 뒤 같은 metrics에 다시 적용하면 다음이다.

```text
overall_pass: true
phase3_bridge_ready: true
evidence_count: 8 / 2 required

avg_abs_rel shift=1 wrong-position delta MSE: 0.000231
avg_abs_rel sweep max delta MSE:              0.000872
```

**시사점**

Phase 2D에서 가장 중요한 긍정 신호는 Average Pooling positional이 position-only보다 content-sensitive하다는 점이다. 특히 cosine, frozen decoder NLL, shuffled-label delta에서 차이가 났다.

```text
average_pool_abs_rel_pos cosine: 0.547923
position_only_abs_rel_pos cosine:0.337834

average_pool_abs_rel_pos shuffled head delta: 0.800918
position_only_abs_rel_pos shuffled head delta:0.448569
```

이는 expander가 positional scaffold만 쓰는 것이 아니라 Average Pooling latent의 sample-specific content도 사용한다는 뜻이다.

하지만 가장 강한 반론도 유지됐다. `gaussian_noise_abs_pos`는 MSE, cosine, decoder NLL, token-head NLL, shuffled-label delta, meaningful generation에서 대체로 가장 강했다.

```text
gaussian_noise_abs_pos MSE:            0.014640
gaussian_noise_abs_pos cosine:         0.724751
gaussian_noise_abs_pos decoder dNLL:   4.034742
gaussian_noise_abs_pos token-head dNLL:0.047338
gaussian_noise_abs_pos meaningful gen: 0.500000
```

따라서 Phase 2D의 정직한 결론은 다음이다.

> Phase 2D는 Phase 3A로 넘어갈 수 있게 해줬다. 그러나 Phase 3A는 반드시 position-only와 Gaussian positional controls를 함께 둬야 한다. token objective가 Average Pooling content latent를 강화하는지, 아니면 positional shortcut과 Gaussian-like noisy hidden path를 더 강화하는지 검증해야 한다.

Phase 3A의 primary condition은 `average_pool_rel_pos`가 가장 적절해 보인다. 이유는 Average Pooling이 잃어버리는 block 내부 위치 정보를 직접 보완하고, Phase 2D에서 Average Pooling positional 계열 중 frozen decoder delta NLL이 가장 낮았기 때문이다.

```text
primary:   average_pool_rel_pos
secondary: average_pool_abs_rel_pos
controls:  position_only_rel_pos, position_only_abs_rel_pos, gaussian_noise_abs_pos, h0_decoder_control
```

### Phase 3A. Generation-aware Reverse Objective

**목적**

Phase 3A는 reverse expander 학습에 token-level objective를 직접 넣어 generation-readable hidden state가 만들어지는지 확인했다.

구체적으로는 Phase 2B 이후 사용하던 lightweight token head를 원본 `h0`에서 먼저 학습한 뒤 freeze하고, expander loss에 token-head cross entropy를 추가했다.

```text
L = L_hidden_mse
  + lambda_cos * L_cos
  + lambda_var * L_var
  + lambda_token * L_token_head
```

Primary arm은 Phase 2D에서 정한 `average_pool_rel_pos`였고, `lambda_token = 0.05, 0.10, 0.20` sweep을 실행했다. Position-only controls와 Gaussian controls도 같이 유지했다.

**결과**

Strict overall pass는 실패했다.

```text

P3A-G-TOKEN-HEAD: pass
P3A-G-DECODER: fail
P3A-G-LATENT-USE: pass
P3A-G-CONTENT-CONTROL: pass
P3A-G-GENERATION: fail
P3A-G-GAUSSIAN-GAP: fail
overall_pass: false
phase3a_success: false
best_average_pool_rel_token_arm: average_pool_rel_pos_tok020
```

핵심 수치:

```text
average_pool_rel_pos_recon:
MSE:            0.020693
Cosine:         0.550328
Decoder dNLL:   4.909255
Head dNLL:      0.471910
Meaningful gen: 0.000000

average_pool_rel_pos_tok020:
MSE:            0.035089
Cosine:         0.312245
Decoder dNLL:   6.034574
Head dNLL:     -2.051497
Meaningful gen: 0.000000

gaussian_noise_abs_pos_recon:
MSE:            0.014822
Cosine:         0.720791
Decoder dNLL:   4.082911
Head dNLL:      0.025488
Meaningful gen: 0.416667

gaussian_noise_abs_pos_tok010:

```

**시사점**

Phase 3A에서 가장 중요한 발견은 token-head objective가 매우 잘 최적화됐지만, generation으로 이어지지 않았다는 점이다.

`average_pool_rel_pos_tok020`은 token-head delta NLL을 `0.471910`에서 `-2.051497`까지 낮췄다. 이 값이 음수라는 것은 reconstructed hidden이 원본 `h0`보다 frozen token head에 더 잘 맞는 방향으로 이동했다는 뜻이다.

하지만 동시에 MSE는 나빠지고, cosine은 낮아지고, frozen decoder delta NLL은 악화됐다.

```text
MSE:          0.020693 → 0.035089
Cosine:       0.550328 → 0.312245
Decoder dNLL:4.909255 → 6.034574
Generation:  0.000000 → 0.000000
```

따라서 이번 결과는 다음을 의미한다.

> 현재 lightweight token-head loss는 generation-aware objective가 아니라 proxy classifier objective에 가깝다. 이 loss는 token-head decision boundary에는 잘 맞지만, frozen T5 decoder가 읽을 수 있는 hidden manifold에서는 멀어지게 만든다.

Gaussian control도 같은 결론을 강화한다. `gaussian_noise_abs_pos_recon`은 meaningful generation 0.416667을 보였지만, 여기에 token loss를 넣은 `gaussian_noise_abs_pos_tok010`은 token-head NLL이 크게 좋아졌음에도 meaningful generation이 0으로 붕괴했다.

즉 문제는 Average Pooling compression만의 문제가 아니다. 현재 token-head objective 자체가 decoder-compatible generation behavior와 잘 맞지 않는다.

현재 방어 가능한 결론:

> Token-head proxy를 훈련 objective로 직접 넣는 Phase 3A 방식은 LACE generation path를 살리지 못했다. 다음 실험은 token-head를 더 세게 넣는 것이 아니라, frozen decoder와 호환되는 objective를 설계해야 한다.

## 5. 현재까지의 종합 판단

지금까지의 연구는 LACE 가설을 입증했다기보다, 어떤 조건에서는 신호가 살아 있고 어떤 조건에서는 confound가 큰지를 분리한 단계다.

### 확인된 것

1. Frozen T5 encoder latent cache와 Kaggle 실험 pipeline은 안정적으로 동작한다.
2. Token budget compression stage는 자연스러운 정보 손실 곡선을 만든다.
3. Reverse expander는 압축 latent에서 `h0`를 어느 정도 복원하도록 학습된다.
4. Average Pooling은 learned attention보다 안정적인 초기 baseline이다.
5. Average Pooling은 random selection보다 representation direction과 decoder bridge에서 우호적인 신호를 보였다.
6. Matched Gaussian 비교에서도 Average Pooling은 frozen decoder NLL과 latent-use 신호를 유지했다.
7. Explicit positional encoding은 reverse expansion을 크게 안정화한다.
8. Phase 2D에서 Average Pooling positional은 position-only보다 content-sensitive한 신호를 보였다.
9. Block-relative positional scaffold는 Phase 3A의 primary condition으로 쓸 만큼 해석 가능하다.
10. Phase 3A에서 token-head loss는 proxy NLL을 낮췄지만 decoder/generation behavior와는 어긋났다.

### 아직 입증되지 않은 것

1. Compression forward process가 Gaussian/noise corruption보다 전반적으로 우수하다는 주장.
2. Average Pooling compression이 hidden-state MSE/cosine에서 일관되게 우위라는 주장.
3. Average Pooling의 token proxy 개선이 일반적인 token information 보존이라는 주장.
4. Reconstructed `h0_hat`가 open-ended generation에 충분히 decoder-readable하다는 주장.
5. Positional Encoding 개선이 content latent 때문이라는 주장.
6. Learned Attention Compression이 pooling보다 나은 adaptive compression이라는 주장.
7. Token/generation objective를 넣었을 때 compression path가 Gaussian positional보다 좋아진다는 주장.
8. Lightweight token-head objective가 generation-aware objective로 충분하다는 주장.

### 현재 가장 중요한 병목

현재 병목은 단순히 "MSE를 더 낮추자"가 아니다. Phase 2B와 2C를 거치며 더 분명해진 병목은 다음이다.

> Reconstructed hidden state가 teacher-forced proxy에서는 일부 개선되어도, open-ended generation에서 안정적으로 decoder-readable하지 않다.

또 다른 병목은 positional confound다.

> Positional scaffold는 매우 강하지만, 이것이 content compression의 효과인지 position prior의 효과인지 아직 충분히 분리되지 않았다.

## 6. 다음 연구 방향

### 6.1 Phase 3B: Decoder-compatible Reverse Objective

Phase 3A 결과상 다음에는 token-head proxy가 아니라 decoder-compatible objective로 이동해야 한다.

현재 가장 유력한 방향은 frozen T5 decoder의 teacher-forced NLL을 훈련 loss에 직접 포함하는 것이다.

```text
L = L_hidden_rec
  + lambda_cos * L_cos
  + lambda_decoder * L_decoder_nll
```

검증해야 할 것은 다음이다.

1. decoder objective를 넣으면 Average Pooling positional의 open-ended generation이 0에서 벗어나는가?
2. latent ablation/swap sensitivity가 유지되는가?
3. position-only가 같은 decoder objective에서 여전히 강한가?
4. Gaussian positional이 계속 더 강하다면, compression forward보다 length-preserving corruption path가 generation에 더 적합한 것인가?

### 6.2 Learned Attention Compression 재검토

Learned Attention Compression은 아직 버릴 후보는 아니다. 다만 현재 상태에서는 바로 본 실험으로 올리기 어렵다.

필요한 보완:

```text
L_anchor = MSE(z_attention, stopgrad(pool(h0)))
L_direct = MSE(Expand(z_t), h0)
L_scale = mean/variance matching
```

이 보완 후에야 learned attention을 Average Pooling과 공정하게 비교할 수 있다.

## 7. 현재 연구노트의 임시 결론

LACE의 핵심 아이디어인 "Compression, Not Corruption"은 아직 입증되지 않았다. 그러나 완전히 사라진 것도 아니다.

현재까지의 가장 강한 긍정 신호는 다음이다.

1. Average Pooling은 random selection보다 구조적인 representation direction을 남긴다.
2. Matched Gaussian 조건에서도 Average Pooling은 frozen decoder NLL과 latent-use에서 살아 있는 신호를 보였다.
3. Positional Encoding은 reverse expansion을 크게 안정화하며, 이 요소는 generation-capable LACE 설계에서 중요해 보인다.

가장 강한 부정 또는 경고 신호는 다음이다.

1. MSE/cosine 기준에서는 Gaussian 계열이 자주 강하다.
2. Token-head proxy에서는 Gaussian 또는 position-only가 Average Pooling보다 강한 경우가 있다.
3. Average Pooling 기반 reconstructed hidden은 아직 open-ended generation을 회복하지 못했다.
4. Positional Encoding의 효과가 content compression이 아니라 position prior일 가능성이 크다.

따라서 현재 연구의 정직한 위치는 다음이다.

> LACE는 아직 성공한 모델이 아니라, language diffusion forward process를 corruption에서 compression으로 바꿀 수 있는지 검증하는 진행 중인 연구다. 지금까지의 실험은 Average Pooling compression에 일부 decoder-readability와 latent-use 신호가 있음을 보였지만, generation-capable path로 이어지려면 positional confound 정리와 token/generation-aware objective가 필요하다.
